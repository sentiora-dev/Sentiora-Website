01 / Burning

Six ways to write a disc.

Data and ISO images, a Red Book audio CD that plays in any car stereo, a bootable USB stick written sector by sector, MultiDisc for a set larger than the media, and raw SCSI writing for when you want the drive under your own hand.

02 / Before you burn

See what will fit, and what will happen.

The gauge fills as you add files, so the disc is either large enough or it is not — before anything is written. File lists can be saved and loaded again, so a set you burn every month is not rebuilt every month. Finalise, eject, verify afterwards, write the checksum list onto the disc, or stage to the hard drive first so a slow source cannot starve the burn.

03 / Media

From a 700 MB CD to a 100 GB BDXL.

Pick what you are burning to and the gauge recalculates against it. The write speeds offered are the ones your drive actually reports it can do, read from the drive itself rather than taken from a fixed list.

04 / Rescue

A scratched disc does not die all at once.

Sectors die. Recovery reads through them one at a time, notes the ones that refuse and carries on rather than stalling at the first obstacle, then comes back to the skipped ones up to eight times. What still will not read is written into a list with each sector's exact position — you are never told "done" over a file with a hole in it.

05 / ISO and audio

Images, without a disc in the drive.

Build an ISO from files and burn it whenever. Turn a BIN, IMG or Nero NRG into a standard ISO any program can open. Pull files out of an image without burning or mounting it — ISO9660 and Joliet long names both understood. And lift an audio CD into MP3, FLAC or WAV, naming the tracks yourself or leaving them numbered.

06 / Light or dark

Both, at one click.

The same screens in a dark theme, switched from the title bar. Every screen and message is translated into twelve languages — Romanian, English, Spanish, French, German, Italian, Portuguese, Russian, Arabic, Chinese, Hindi and Bengali.

02 / RESCUE

The day the disc will not read

  • Erase disc — empties a rewritable one, quickly or completely Free
  • Copy disc — clone to another disc, or save it as an image on the hard drive
  • Recover data — sector by sector, skipping the dead ones so it never stalls, then returning to them up to eight times
  • CD recovery (C2) — a second pass over only what is left: sub-block reads, the drive's own C2 error information, up to sixteen attempts, taking the variant that repeats most often
  • Verify disc — the written disc compared against the image it came from, byte by byte

04 / TOOLS

For the archive you will open in ten years

  • Reed-Solomon protection — the file split into 16 slices with up to 32 spare ones kept alongside; if it later decays, they rebuild it
  • And it checks the rebuilt file against fingerprints taken while it was whole — if they disagree it says it failed and deletes the result, rather than handing you something that only looks intact
  • Encrypt / decrypt — AES-256-GCM, the key derived by PBKDF2-SHA256 over 600,000 iterations, every chunk numbered and authenticated. No back door: forget the password and the file is gone, to us as well
  • File checksum — CRC32, MD5 or SHA-256
  • Disc diagnosis — what is really in the drive: blank or written, how many sessions, where writing can continue, how much is left
  • Operations journal — what you did, when, how long it took and how it ended Free

/ Release

Checked, not assumed.

Verification does not mean "written without an error". It means the disc is read back and compared with what it should contain, byte by byte — and if the check does not reach the end, for any reason, it says plainly that it did not finish rather than passing it off as a success. The fingerprint list is saved beside your files as a standard SHA256SUMS.txt, so in ten years you can check that disc on any computer, with certutil or sha256sum, without this program at all.
